# Team Roles — SE302 Coursework

This document defines the roles and responsibilities for our Software Testing group project.

We are organized into **two pairs**: a **coding pair** and a **documentation pair**. Each member has a clear role, but we support each other and everyone writes their own individual summary report at the end.

---

## Role 1 — Team Leader / Test Manager
**Pair:** Coding Pair  
**Member:** _TBD_

### Responsibilities
- Overall project coordination and final accountability
- Set internal deadlines, run check-ins, manage Moodle submission
- Write the **Test Plan** document (testing strategy, scope, dependability criteria, environment, entry/exit criteria)
- Review test cases for quality and track progress across both pairs
- Collect individual summary reports and consolidate the final report
- Lead the presentation

### Q&A Focus
Strategy, scope decisions, team coordination.

---

## Role 2 — Developer / Test Implementer
**Pair:** Coding Pair  
**Member:** _TBD_

### Responsibilities
- Partner with the Team Leader on all technical work
- Work on the application code and implement the **proposed change** to the system
- Write and run the actual tests based on the test cases designed by the documentation pair
- Capture execution evidence (screenshots, logs, defect reports) and share with the documentation pair
- Handle environment setup: test data, multi-user accounts, file I/O fixtures

### Q&A Focus
Implementation of the change, regression testing, defects found.

> **Coding pair note:** The two coding members split the work between them — one focuses more on the proposed change, the other more on test execution, or they pair on both.

---

## Role 3 — Test Designer / Requirements Analyst
**Pair:** Documentation Pair  
**Member:** _TBD_

### Responsibilities
- Own **what to test**
- Write the **Background** section of the report (system specification: features, architecture, user roles, data flow)
- Derive quality criteria and dependability checklists from the requirements
- Design the **formal test cases with expected results** and hand them to the coding pair to run
- Build the traceability matrix (which test covers which requirement)
- Write the **Introduction** section

### Q&A Focus
Why these test cases, why these boundaries, what's covered.

---

## Role 4 — Documentation Lead / Results Analyst
**Pair:** Documentation Pair  
**Member:** _TBD_

### Responsibilities
- Own the **write-up of what happened**
- Take execution evidence from the coding pair and write **"Detailed Outcome of Each Testing Step"** — the biggest testing-content section
- Write the **Conclusion**
- Format the report to UKH academic style, build Table of Contents, List of Figures/Tables
- Manage references and citations
- Keep the report under 6000 words

### Q&A Focus
Test results, defect patterns, what we learned.

---

## Workflow

1. **Documentation pair** designs test cases
2. **Coding pair** implements the system change and runs the tests
3. **Coding pair** sends results and evidence back
4. **Documentation pair** writes up the outcomes
5. **Team Leader** reviews and consolidates the final report

> ⚠️ The documentation pair must deliver test cases **early**, otherwise the coding pair will be blocked on execution.

---

## Shared Responsibilities

Every team member is responsible for:

- Writing their own **1–2 page individual summary report** (role, contributions, lessons learned)
- Preparing their part of the **presentation**
- Understanding the whole project well enough to handle Q&A questions outside their direct area
